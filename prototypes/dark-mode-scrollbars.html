Four ways to paint it

Every box holds the same text on the theme's card surface. Scroll with the trackpad and hover the thumb: on macOS the scrollbar only appears while you move, so the real judgement is in motion. Switch theme up top without losing your place.

Native

Nothing painted. The theme just tells the browser it is dark and the browser draws its own scrollbar — the same one the rest of the system uses.

In light mode nobody looks at the scrollbar: the browser paints a grey channel that melts into the background. Switch the panel to dark and that same factory grey becomes the brightest thing on screen.

The thumb is a control — it gets dragged, hovered and pressed. Too faint and it doesn't read as something you can grab; too strong and it competes with the content sitting right next to it.

What gets decided here is not the colour, it's the weight. Every option draws from the same Lexicon grey ramp, so the only question is how far from the panel the thumb needs to sit.

Scroll this box in light and in dark with the same option selected. If it vanishes in one and shouts in the other, that pair of tokens doesn't weigh the same in both and needs its own value per theme.

The last check is the boring one: hover it and press it. An option that only reads on hover is an option that doesn't read.

How far the thumb sits from its background

Measured in whichever theme is selected above. The reference for anything draggable is 3: below that the thumb reads as decoration rather than as something you can grab. Below 2 it is barely there at all.

What we would need to add

Six new tokens pointing at the ramp we already have, the same way skeletons and charts already do it. Because they point at the ramp they flip with the theme on their own: no separate block for dark, and no colour left hardcoded.

:root {
  --scrollbar-thumb:        var(--color-secondary-l2);
  --scrollbar-thumb-hover:  var(--color-secondary-l1);
  --scrollbar-thumb-active: var(--color-secondary-l0);
  --scrollbar-track:        transparent;
  --scrollbar-size:         12px;
  --scrollbar-radius:       var(--rounded-full);
}

  • The same token does not weigh the same in both themes

    The grey ramp is not an exact mirror of itself: --color-secondary-l2 reads noticeably heavier in dark than in light. We have to decide what should match — the token or the visual weight. If it is the weight, dark needs a pair of its own.

  • Firefox gets no hover

    The colours apply in every browser, but the change on hover, the thickness and the rounded corners only work in Chrome, Safari and Edge. In Firefox the thumb comes out with the same pair of colours at the system thickness.

  • The browser still needs telling

    On top of the tokens, the theme has to declare itself dark to the browser. That is what fixes the scrollbars we cannot paint — native selects, third-party iframes — and the system form controls.

  • Focus cannot be painted

    No browser lets us mark the scrollbar when it holds keyboard focus. If the scrolling box is focusable, the box's own focus ring is all we get.
